# 受力钢筋数量-混凝土梁提示词

> **统一表述规范**：构件名称统一写为「混凝土梁 / 混凝土板 / 混凝土柱 / 混凝土剪力墙 / 混凝土基础」，存在多种构件类型时统一写为「混凝土构件」；结论类型统一为「类型一（全部合格）/ 类型二（存在不合格）/ 类型三（无图纸）」；结论字段统一为「结论表述」；结论中禁止出现楼层范围描述。

## 一、任务目标

依据《混凝土结构工程施工质量验收规范》GB 50204-2015 第5.5.1条（主控项目：受力钢筋的规格和数量必须符合设计要求，全数检查），对混凝土梁构件底排受力钢筋根数检测数据，按“楼层 + 梁编号”逐组逐构件核对设计配筋数量与实测配筋数量是否一致，输出校验明细与校验概述，结论表述必须严格套用下方三类模板（不得增删文字，仅替换数字/表号）。

## 二、判定标准

- 实测根数 = 设计根数 → 符合设计要求（合格）。
- 实测根数 ≠ 设计根数 → 不符合设计要求（不合格）。

## 三、结论模板（须逐字套用，不得改动句式）

| 结论类型 | 适用条件 | 结论表述 |
| :-- | :-- | :-- |
| **类型一（全部合格）** | 不合格构件数 = 0 | 所检混凝土梁构件底排受力钢筋根数均符合设计要求。 |
| **类型二（存在不合格）** | 不合格构件数 ≥ 1 | 所检混凝土梁构件底排受力钢筋根数符合设计要求的有{X}个，不符合设计要求的有{Y}个。 |
| **类型三（无图纸）** | 输入设计值为“/”或明确标注“无图纸” | 所检混凝土梁构件底排受力钢筋根数为实测值，详见表{Z}。 |

- X、Y 填具体构件数，Z 填实际表号。

## 四、执行步骤

1. 按楼层 + 梁编号分组，确保不遗漏。
2. 逐构件比较设计与实测根数，记录异常，格式：`XX层混凝土梁XXX（轴线）设计X根，实测Y根，不符合设计要求`。
3. 统计总构件数、合格构件数、不合格构件数。
4. 若不合格构件数 ≥ 1，选用**类型二**；若全部合格，选用**类型一**；若无图纸，选用**类型三**。将对应数字/表号填入模板，生成结论表述。

## 五、输出 JSON 格式（仅输出此 JSON，不得附加任何文字）

```json
{
  "校验概述": {
    "总构件数": 数字,
    "符合设计要求构件数": 数字,
    "不符合设计要求构件数": 数字,
    "结论类型": "类型一/类型二/类型三",
    "结论表述": "字符串（必须套用上述模板，替换X/Y/Z，不出现楼层）"
  },
  "校验明细": [
    {
      "构件标识": "字符串（如25层混凝土梁L1-A轴）",
      "设计配筋根数": 数字,
      "实测配筋根数": 数字,
      "合格判断结果": "符合设计要求/不符合设计要求",
      "异常说明": "字符串（不合格时写明差异，合格填“无”）"
    }
  ]
}
```

## 六、关键约束

1. 校验明细**仅列出不合格构件**；全部合格时该数组为空（`[]`）。
2. 结论模板中的“{X}”“{Y}”“{Z}”必须替换为真实数值/编号，其余一字不差。
3. 结论中**禁止**描述楼层范围（如“十二层~屋面层”等）。
4. 结论表述中的构件名称一律使用「混凝土梁 / 混凝土板 / 混凝土柱 / 混凝土剪力墙 / 混凝土基础」，多类型时使用「混凝土构件」。
5. 所有数值字段必须为数字类型。
6. 纯 JSON 输出，不输出任何解释性文字或标记。
7. 当设计值输入为“/”时，表示为无图纸项目。
