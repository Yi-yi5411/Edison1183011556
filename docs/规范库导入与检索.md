# 规范库：导入与检索

主体结构检测的规范问答（`search_norms` / `query_norms` / `explain_norms`）基于本地
SQLite 规范库，不联网、不依赖向量库。

- 数据库：`report_generator/data/norm_qa/norm_codes.db`
- 表：`clauses`（条文）+ FTS5 虚拟表 `clauses_fts`（标题、正文）
- 代码：`report_generator/utils/norm_qa/`（store / parser / ingest / engine / catalog / llm）

## 导入真实规范

```bat
cd report_generator
python -m tools.norm_import --coverage                       :: 先看现状
python -m tools.norm_import --dir data/norm_qa/input --dry-run :: 只解析不入库
python -m tools.norm_import --dir data/norm_qa/input --mode rebuild
python -m tools.norm_import "GB 50204-2015 混凝土结构工程施工质量验收规范.md"
```

- 文件名约定 `<代号> <名称>.md`：`JGJT 23-2011 回弹法…`、`GB50204-2015 混凝土…`、
  `JGJ/T 384-2016 钻芯法…` 都能正确拆成代号与名称（`JGJT`/ `GBT` 会自动规范成
  `JGJ/T` / `GB/T`）；拆不准时用 `--code` / `--name` 覆盖（仅单文件）。
- 支持 `.md/.markdown/.txt/.docx`。Markdown 约定：`# 章` / `## 节` /
  `### 条号 标题` + 正文；正文里的 `<!-- tags: 4.1.1, 4.1.2 -->` 表示该条文同时
  归属这些条号，同文件内重复条号只保留最后一条（真实标题优先）。
- `--mode append` 按 `code+chapter` 覆盖同一本规范的条文，不影响其它规范；
  `--mode rebuild` 清空重建。

## 检索行为

1. **条号精确**：问题里出现 `5.1.2` 走精确匹配；出现 `4.1`（节号）返回该节全部子条。
2. **自然语言**：关键词提取 → 同义扩展（`回弹 → 回弹法/测区/碳化深度`）→
   FTS5 MATCH 按 bm25 排序 → 统一打分（用户原词权重 3/2，扩展词 1，整句命中 +4）。
   空结果才降级 LIKE。
3. **按检测项目收敛**：传 `detection_items` 时只在该项目的依据规范里检索；依据规范
   由 `report_narrative.standards_for`（报告第二章依据）解析而来，所以"报告引用的
   规范"和"检索优先的规范"永远同一套。检索不到会自动放开并标记 `filtered_out`。
4. 无结果时返回术语候选（库内出现频次高的片段），供换词重查。
