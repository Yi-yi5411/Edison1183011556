# 报告预检与结论兜底

生成《检测报告》前先跑 **report_preflight**。预检只读，不修改工程、不占用仪器；
**报告抬头、人员、工程概况的空缺/占位只提示，不阻断生成**（可先出报告后补）；
空数据、缺模板、未评定等结构性问题仍会阻断。

实现：`report_generator/utils/report_preflight.py`
接口：`GET /api/report/facts`（附带 preflight）、`POST /api/report/generate`、`POST /api/report/render`

## 一、阻断项（errors）

1. 勾选项目没有有效数据（全空行不算数据）；
2. 勾选项目没有对应的报告结果表模板；
3. 勾选项目尚未评定（`assessment.ok != True`）；
4. 报告日期早于检测日期。

## 二、提示项（warnings）

- 报告编号、工程名称、地点、委托/见证/建设/施工单位、检测/报告日期、
  检测人/编写/复核/审核/批准未填或仍是占位值；
- 工程概况含 `【请填写】`、`{{ }}`、`待定`、`TODO`、`XXX`；
- 设计/监理/勘察单位、结构类型、面积、层数、高度、开竣工日期、检测目的未填；
- 报告编号不符合“前缀-年份-序号”，自动续号可能失效；
- 报告日期早于今天（历史/补发报告）；
- 评定引擎返回的警告（芯样数量不足、离散性大、推定区间过宽等）。

## 三、结论兜底

报告结果表的兜底结论分三种情况：

1. 有强度推定值：按设计等级逐行比对，输出范围 + 满足/不满足；
2. 没有强度值，但“合格/不合格”或“结论”列有逐行判定：按逐行判定输出；
3. 两者都没有：输出“未提供足够数据，无法判定”，**不再默认“满足”**。

对应实现：`utils/report_template_map.build_conclusion()`。

## 四、空数据项目

`build_results()` 对无有效数据的项目不再静默 `continue`，会写入：

- `skipped`：`xxx（无有效数据，未生成一览表）`
- `warnings`：`xxx: 没有有效数据，未生成结果表`

报告预检会在更早一步阻断，因此正式生成不会出现“检测内容列了、结果表没有”的静默缺项。

## 五、当前策略

- 报告信息未补全时可直接生成，生成结果 `warnings` 会列出待补字段；
- 正式对外前建议再补全建设单位/施工单位/人员/工程概况；
- 未评定或空数据项目仍不能生成，避免结论缺失或结果表为空。
