# 人机协同与安全门（P6）

写操作分两级，安全门集中在 MCP 服务端执行；人工回退靠工程备份。

## 1. 工具分级

| 级别 | 参数要求 | 注解 | 数量 |
|---|---|---|---|
| 只读 | 无 | `readOnlyHint=true` | 58 |
| 普通写 | `confirm=true` | `destructiveHint=false` | 38 |
| 危险写 | `confirm=true` + `confirm_delete=true` | `destructiveHint=true` | 13 |

危险工具（删除/覆盖，不可恢复）：

`delete_record`、`delete_equipment`、`delete_personnel`、
`delete_report_template`、`delete_original_template`、`delete_wiki_page`、
`delete_sheet_rows`、`reuse_original_record`（覆盖工作表）、
`import_file`、`import_sheet_excel`、`import_assessment_excel`（默认覆盖）、
`import_norms`（rebuild 全量重建）、`restore_project`。

```jsonc
// 调用示例：删除报告记录
{ "kind": "report", "record_id": "ab12…", "confirm": true, "confirm_delete": true }
```

## 2. 安全门

`mcp_server._call_tool` 统一执行，不依赖各 handler：

1. 未知工具 → `未知工具：x`；
2. 写工具缺 `confirm` → `写操作需要用户确认：请在参数中传 confirm=true。`；
3. 危险工具缺 `confirm_delete` → `危险操作需要二次确认：<tool> 会删除或覆盖数据且不可恢复，确认后请传 confirm_delete=true。`；
4. 通过后执行，异常原样抛出。

## 3. 审计

每次**写**调用（含被第 2/3 步拦下的）追加一行 JSON 到 `data/audit/mcp_writes.jsonl`：

```json
{"ts":"2026-11-12 09:41:05","tool":"put_rows","danger":false,"ok":true,
 "duration_ms":12,"error":"","args":{"sheet_key":"剪力墙厚度检测","rows":[["1"]],"confirm":true}}
```

- 密钥类字段（`api_key`/`password`/`token`/`secret`/`authorization`）置 `***`；
- 字符串超 800 字截断、数组只留前 50 项、嵌套深度 5；
- 文件超 5MB 轮转为 `mcp_writes.jsonl.1`；
- 路径可用 `STRUCTURAL_AUDIT_DIR` 覆盖；审计失败静默，不影响业务。

## 4. 人工回退

- `GET /api/project/backups`（MCP `list_project_backups`）：列出 `data/projects/backups/`；
- `POST /api/project/restore`（MCP `restore_project`，危险）：先把当前工程另存为
  `restore_<时间戳>.json` 再加载备份，误操作可逆；
- “新建工程”本身也会先把旧工程备份到同一目录。

## 5. 审计复核

`get_audit_log`（只读，不写审计）支持 `limit` / `tool` / `only_failed`，
用于回答“刚才改了什么”“有没有被拦下的危险操作”。返回最近的在前。

## 6. 计划 / 中断

计划、目标、子智能体、审批、中断都由 DSH 原生提供；MCP 侧只保证：
长任务有可轮询句柄（`scan_job`），危险动作有二次确认，所有写操作留痕。
