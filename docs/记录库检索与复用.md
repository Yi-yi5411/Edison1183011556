# 记录库：历史检索与数据复用

报告库与原始记录库统一存在 `data/records/records.db`。原始记录在生成时会保存
工程快照（`snapshot_json`，超过 1MB 标记 truncated），因此可以**把历史数据搬回新工程**。

## 检索

`GET /api/records/similar?q=&kind=both|report|original&project=&limit=`
（MCP：`find_similar_records`）

- 多字段加权：项目名 5 / 检测项（sheet_key、base_item）4 / 报告编号 4 / 模板 2 / 文件路径 1 / 结论 3；
- 中文不分词：整句 + 2~4 字片段，2 字片段权重减半，避免通用词刷分；
- 原始记录的结论从快照里读（只解析前 100 条、≤256KB 的快照）；
- 返回 `score` 与 `matched_fields`，可解释；无查询时按生成时间倒序。

## 复用

1. `GET /api/records/original/{id}/sheets`（MCP：`list_record_sheets`）
   列出快照里的表，并把历史列与**当前列定义**比对：
   `compatibility = {compatible, missing_columns, extra_columns, needs_reorder}`。
2. `POST /api/records/original/{id}/reuse` `{sheet_key?, append?}`
   （MCP：`reuse_original_record`，写操作需 `confirm=true`）

复用规则：

- **按列名对齐**：同名列重排、当前新增列补空、历史独有列丢弃并写入 `warnings`；
- **默认覆盖**目标表，`append=true` 追加；
- 覆盖时恢复当时的**钻芯参数**（影响表格结构与重算）与**评定原始输入**；
- 写入统一走 `webapp/backend/sheet_apply.apply_rows_to_sheet`，与 Excel 导入/粘贴同一份逻辑，
  写完立即重算并自动加入勾选项；
- 快照没有保存（旧记录）时返回 400「该原始记录没有保存工程快照，无法复用」。

## 界面

`/records` 页面：报告/原始记录列表、详情、快照下载、删除；检索与复用通过接口/智能体调用。

## 测试

`python tests/test_record_reuse.py`（36 项）：

- 打分排序、分词、命中字段；
- 单表/工程级快照解析、列比对、行重排补空；
- **数据往返**：行 → 评定 → 快照 → 还原 → 再评定，结论类型与表述完全一致；
- 真实记录库：3 条带快照的记录能列出表、复用 6 行、追加后 12 行，用后还原工程状态；
- 无快照记录给出可读错误；
- 三个端点与 MCP 工具（写工具带 confirm）。
