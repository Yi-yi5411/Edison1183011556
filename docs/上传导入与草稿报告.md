# 上传导入、自动评定与草稿报告

本文说明 2026-11 之后采集入口的行为变化：**上传的文件先识别、由用户确认，再入库并自动评定；报告不再要求先勾选，数据不全时可以生成草稿。**

## 1. 要解决的问题

旧流程是“勾选驱动”：新建工程 → 勾选检测项目 → 打开采集页 → 导入/录入 → 评定 → 生成报告。由此产生三个问题：

- 只在项目区/对话区上传文件时，文件只落在 `data/uploads`，不解析、不入库、不勾选，报告看不到；
- 有数据但未勾选的项目被报告排除；
- 数据不齐时只能整份报告失败，不能先出草稿。

现在的目标是：**上传 → 识别 → 确认/校正 → 入库 → 自动评定 → 就绪项出报告；不足的项回到采集页补录。**

## 2. 对话页上传表格

支持 `.xlsx/.xlsm/.csv/.docx/.doc`（`.doc` 先转 `.docx`）。上传成功后：

1. 文件保存到 `data/uploads/YYYYmmdd_HHMMSS_<安全文件名>`；
2. 前端调用 `GET /api/ingest/recognize` 只读识别，不写工程；
3. 弹出“确认识别结果”对话框，展示：
   - 文件类型、行数、列数；
   - 按表头命中率排序的候选检测项目（含匹配列数、缺失列）；
   - 构件下拉（来自该检测项目的全部构件，默认取识别出的构件）；
   - 可编辑的目标工作表名（`检测项目（构件）`）；
   - 参数化项目的采集参数表单；
   - 前 10 列表头与 3 行样例。
4. 用户可改选检测项目/构件、修正工作表名、补参数；确认后调用
   `POST /api/ingest/import`（`auto_assess=true`）。

识别错误时，单元格内容不在上传阶段改；导入后到采集页逐格校正即可。这样避免在上传弹窗里重做一套表格编辑器。

“仅作为附件”按钮只把文件路径加入对话输入框，不写工程。识别候选不可用或用户只想让 AI 看文件时使用。

### 参数化项目

钻芯法、回弹钻芯修正法、砖强度等项目的列结构依赖采集参数（楼栋、构件数、每构件芯样数、设计强度等级、芯样直径等）。

- 候选带 `requires_setup=true` 和 `param_specs`；
- 前端先调用 `POST /api/project/check_item`，带 `params` 建结构化工作表；
- 再导入数据，避免“先导入 26 行、再建 20 行参数表”把数据覆盖；
- 后端 `import_into_sheet` 也会兜底：目标表未建且项目需要参数时直接返回 400，提示先补参数。

## 3. 入库与自动评定

`POST /api/ingest/import` 复用 `sheet_apply.apply_rows_to_sheet`：

- 按表头匹配列，支持覆盖/追加；
- 立即重算计算列；
- 自动把工作表加入 `checked_items`（即使之前没勾选）；
- `auto_assess=true` 时立即调用评定引擎，把结果写回 `assessment_results/options`。

返回 `assessment` 与 `ready`（`assessment.ok`）。评定失败不会阻断导入，前端显示错误并允许去采集页补录。

同时修复了 `check_item`：工作表已有数据但不在 `checked_items` 时，不再提前返回“已勾选”，而是补入勾选列表。

## 4. 报告纳入范围

报告不再只看 `checked_items`，而是：

1. 先取 `checked_items` 中在 `sheet_data` 且有有效行的项；
2. 再补 `sheet_data` 中其它有有效行的项（去重）。

因此“没勾选、只上传了数据”也能生成报告。报告信息自动整理、事实包、报告预检使用同一口径。

有效行判定：任一单元格 `strip()` 后非空。

## 5. 草稿报告

报告页新增“草稿：仅生成已就绪项”复选框，请求体 `{draft: true}`。

草稿模式只纳入同时满足以下条件的项：

- 有有效数据行；
- 模板库能解析出该检测项目/构件的结果表模板；
- `assessment_results[sheet_key].ok` 为真。

其余项写入 `skipped_items[{sheet_key, reason}]`，报告页在结果卡中列出“草稿已跳过以下未就绪检测项”。没有任何就绪项时返回 400，并说明原因。

非草稿模式仍是严格模式：纳入范围内有未评定项时，报告预检会报错。

## 6. 图片与扫描件

对话页/工作区上传图片或 PDF 后，走同一条“OCR → 识别表格 → 确认检测项目 → 写入工程 → 评定 → 报告草稿”链路：

1. 前端调用 `POST /api/scan/submit` 创建异步作业，按 1.5 秒轮询 `GET /api/scan/job/{id}`；通常 20~30 秒完成。
2. 识别结果包含检测项目、置信度、列头、结构化行、字段警告。
3. 弹窗展示识别项目/行数，并调用 `GET /api/scan/targets?detection_item=` 得到目标采集表：
   - 无构件项目只有一张表；
   - 有构件项目按构件列出，可改选构件或已有表；
   - 参数化项目显示采集参数表单。
4. 用户可改选检测项目、构件、目标表，修正参数；确认后调用 `POST /api/scan/commit`：
   - 按列头归一化对齐后写入；
   - 只把目标表加入 `checked_items`，**不清空、不批量勾选其它项目**；
   - 立即重算并自动评定。
5. 参数化项目若目标表尚未建立，前端先调用 `POST /api/project/check_item` 带 `params` 建结构化空表，再提交扫描结果。
6. 点“导入、评定并生成报告”时，导入成功后立即调用 `POST /api/report/generate`（`draft:true`），在弹窗内直接查看报告草稿；也可以稍后到报告页生成。

识别错误时可以改选检测项目/构件，或点“仅作为附件”不写工程；附件模式下如仍需要文字，可调用 `POST /api/scan/ocr-text` 把 OCR 文本放进输入框。未提到的检测项目保持原状。

扫描作业持久化在 `data/scan_jobs.json`；后端重启后仍可查到已完成/失败作业，运行中的作业标记为 `interrupted`。扫描相关相对路径统一按项目根解析。

## 7. API 与代码位置

| 用途 | 接口/文件 |
| --- | --- |
| 只读识别 | `GET /api/ingest/recognize?filepath=&sheet_name=` |
| 导入并评定 | `POST /api/ingest/import` `{filepath,sheet_key,sheet_name?,append?,auto_assess?,params?}` |
| 参数建表 | `POST /api/project/check_item` `{sheet_key,checked:true,params}` |
| 扫描作业 | `POST /api/scan/submit`、`GET /api/scan/job/{id}`、`GET /api/scan/jobs` |
| 目标采集表 | `GET /api/scan/targets?detection_item=` |
| 扫描写入并评定 | `POST /api/scan/commit` `{job_id,sheet_key,append?,params?,auto_assess?}` |
| 报告生成 | `POST /api/report/generate`、`/generate/stream`，新增 `draft` |
| 后端 | `webapp/backend/ingest.py`、`routers/ingest.py`、`routers/report.py`、`routers/project.py` |
| 前端 | `webapp/frontend/src/views/ChatView.vue`（表格确认弹窗、扫描确认弹窗）、`ReportView.vue`（草稿） |

相对路径统一按项目根解析，不再依赖后端进程当前目录。

## 8. 已知限制

- 上传确认弹窗只做“项目/构件/工作表/参数/表头预览”级别校正，不提供逐单元格编辑；单元格错误到采集页改。
- 草稿只按“结果表模板是否存在”判断就绪，不判断报告章节文字是否完整。
- 参数化项目仍需要用户确认参数，不会从文件里自动推断楼栋/构件数等。
- 扫描结果中的 `field_warnings` 目前按原始 JSON 字符串展示，尚未格式化；导入后可到采集页逐格校正。
- 单张图片/PDF 的 OCR + 表格识别通常需要 20~30 秒；同一时间只处理一个扫描作业。
- 上传图片默认进入扫描确认流程，不再自动把 OCR 文本塞进输入框；需要纯文本时可使用“仅作为附件”回退。
